# 代码维护规则

算法库采用现代 ACM C++ 风格，网页与 PDF 展示同一份代码。格式以仓库根目录 `.clang-format` 为准。

- 使用 4 空格缩进、同行左大括号、正常运算符和逗号空格。保留短小函数，避免把多步操作压在同一行。
- 64 位有符号整数别名统一为 `using i64 = long long;`，128 位整数使用 `i128`。保留 `long double`、无符号整数等实际精度和符号属性，数值字面量后缀按原类型保留。
- 使用普通函数或轻量 `struct`，允许 `vector`、`array`、STL 和 lambda。沿用清楚的竞赛命名；已有接口不为缩短名称而改名，动态容器不强制改成全局数组。
- 解释性注释外移到紧邻代码的 Markdown：初始化、下标、区间开闭、参数和返回值写入使用说明；复杂度和适用条件单列；核心不变量写入必要原理。合并重复内容，省去逐行复述和修复历史。
- 作者、出处及授权信息保留在对应正文或来源说明中；编译、展示必需的指令与 `@book-begin` / `@book-end` 标记留在代码中。
- 同一个实现由网页与 PDF 引用同一代码文件；短小讲解示例可留在正文。
- `@book-begin` / `@book-end` 内是实际展示代码，标记外保留独立编译所需的头文件、宏和入口。修改展示区域时同时检查两端输出与编译。
- 修改算法逻辑需要任务明确涉及该修复，并提供与行为相关的验证；单纯收录与排版任务只整理内容与引用。

新增实现按以上约定整理。独立文件的 GNU++20 语法检查与依赖上下文片段的验证分别报告；缺少回调或依赖的骨架在代码前说明待接入部分。复杂度按实际实现核对，明确均摊、期望和最坏界。

使用 `uv run --with clang-format==22.1.0 clang-format -i <文件>` 重现格式。修改后检查别名、字符串字面量、预处理指令和展示区域，确认格式整理没有改变算法行为。
