# 代码维护规则

当前算法库以 Templates-XCPC 的固定提交为来源，迁入后独立维护。维护已有实现时沿用它自己的接口、类型、命名和大括号风格。

- 保留 `std::` 限定或命名空间使用方式、类型别名、常量及其依赖关系。
- `ld`、`long double`、`i64`、`LL` 等按原定义处理。尤其不能将 `long double` 改为 `double`，也不能因本地模板头缺少别名而改变数值类型。
- 保留作者、出处、复杂度、使用限制和初始化要求的注释；信息不足时明确指出需要的调用上下文，不编造保证。
- 同一个实现由网页与 PDF 引用同一代码文件；短小讲解示例可留在正文。
- `@book-begin` / `@book-end` 内是实际展示代码，标记外保留独立编译所需的头文件、宏和入口。修改展示区域时同时检查两端输出与编译。
- 修改算法逻辑需要任务明确涉及该修复，并提供与行为相关的验证；单纯收录与排版任务只整理内容与引用。

新增实现优先采用所在条目或相邻实现的风格，不引入新的全站模板头规范。独立文件的 GNU++20 语法检查与依赖上下文片段的验证应分别报告。
