# PDF 清单读取与恢复

对应 issue #2。下载中心与章节 PDF 卡片继续共用 `.vitepress/theme/manifest.ts`。

## 有效清单

- `generatedAt` 是可解析的日期字符串；它用于记录生成时间，不作为构建版本标识。
- `targets` 非空，必须恰好包含 `id: all`、`type: site` 的整本目标。章节目标为 `type: chapter`，不能使用 `all`。
- ID 唯一，仅含 ASCII 字母、数字、下划线和连字符；标题不能空白。
- 每个目标必须有 `pdf`，地址为生产端现有的 `pdfs/<id>.pdf`，大小为正安全整数。
- 拒绝旧 `templates` / `pdfs` 结构。不恢复旧版式兼容。
- 任一目标无效则整份拒绝，避免不同入口使用不同的部分清单。允许只有整本的清单；加载器不持有另一份章节目录，因此不检测缺失的章节。

## 请求、缓存与界面

- 同时加载的调用方共享一个请求；成功结果在当前页面会话内缓存，整页刷新后重新获取。
- 网络、HTTP、JSON 和结构错误统一返回不可用结果，不保留失败缓存。后续调用可以再次请求。
- 两个入口显示不可用提示和“重试”按钮。点击后显示加载中，完成后恢复链接或再次提示失败。不后台自动重试。
- 请求使用 `cache: no-cache`，让 HTTP 缓存重新验证清单；下载地址继续通过 VitePress `withBase` 处理部署子路径。

## 版本边界

本轮按当前结构与固定目标地址判断兼容性，不引入 schema version、内容哈希或构建 ID。HTTP 重新验证能减少旧缓存直接命中，但不能证明 HTML、清单和 PDF 属于同一构建，也不探测 PDF 文件是否存在。格式正确的旧清单仍可能被接受；打开的页面会保留已成功读取的清单，刷新页面可重新获取。严格部署版本绑定属于后续独立变更。

## 验证边界

沿用 issue #2 的公开接口及真实调用方边界：Node 测试通过生产 `loadManifest` 和真实 HTTP 响应验证校验、并发共享及失败恢复，仅适配 VitePress 部署 base。浏览器 smoke 验证下载中心和章节卡片的失败提示、重试与恢复后的链接，并保留正常预览、章节选择、移动端及子路径检查。移动端原有布局隐藏章节侧栏，不新增移动端卡片。

测试不读取私有缓存变量，不改变 CI 发布门禁，不涉及 PDF 排版或重新编译契约。
