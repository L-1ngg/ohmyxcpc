# 设计决策记录

> 本文档保留项目关键技术决策的背景与理由，供后续维护参考。
> 原 `roadmap.md` 中的里程碑清单已全部完成，不再保留。

## 技术选型

| 决策点 | 选择 | 理由 |
|---|---|---|
| 站点框架 | VitePress 1.6 | 配置即 Node 代码，动态 sidebar 无需插件；Markdown 生态成熟 |
| PDF 排版引擎 | **Typst** | 模板化/精排能力强，编译毫秒级，PDF 体积小（字体子集化，单章节约 60–80KB） |
| PDF 备选（已验证后弃用） | Chromium 打印管线 | 所见即所得，但模板化与精排能力不及 Typst；headless 浏览器体积大，且 Chrome 不支持 CSS 页码边距盒 |
| 公式渲染 | markdown-it-mathjax3 **v4** | v5 换底层实现后在 dev 模式下产生 `<style>` 标签导致 Vue 编译崩溃，v4 是 VitePress 官方兼容版本 |
| 搜索 | VitePress 内置 local search（minisearch） | 零外部服务，离线可用 |
| 包管理 | pnpm | 速度快，lockfile 可靠 |

## PDF 导出管线的关键决策

1. **构建时预生成**（整站+章节+页面 × 模板 全量矩阵），网页按钮只做预览与下载——不做运行时在浏览器内编译
2. 所有导出必须含页眉/页码，**不设浏览器打印降级路径**
3. 内置模板 = `standard`（单栏阅读版）+ `double`（双栏赛用紧凑版）
4. 模板即 `.typ` 文件，Typst 编译；浏览器内 WASM Typst 因 CJK 字体打包成本过高而不采用

## 转换层（md → typst）已知限制

`scripts/pdf/md2typst.mjs` 是手写的 Markdown → Typst 转换器，覆盖 XCPC 模板库的内容子集。已处理：标题、段落、粗斜体、行内/块级代码、行内/块级 LaTeX 公式（mitex）、列表、链接、图片、表格、引用、分割线、VitePress 容器（7 种提示卡片）。

**已修复的边界问题：**

- 表头单元格间缺逗号（`table.header([a][b])` 非法）
- `#mi(...)` 后紧跟 `(` 或 `[` 被 Typst 解析为链式调用 → 转换器出口统一插空格断开

## 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| CI/部署机缺少中文字体导致 PDF 乱码 | 中 | CI 安装 Noto CJK；本地需自行安装 |
| md→typst 转换层覆盖不全 | 低 | `pnpm smoke` + 收录时人工抽查 |
| 内容增多后构建/搜索变慢 | 低 | 百页级构建约 4s，余量充足；必要时开启 minisearch 索引分片或改 Algolia |
| 预生成矩阵膨胀（页面数 × 模板数） | 低 | Typst 编译毫秒级；若页面数百级可裁剪为「章节+整站」粒度 |
| typst 版本漂移导致模板语法失效 | 低 | CI 固定 typst 版本（v0.14.2）；脚本支持 `TYPST_PATH` 环境变量 |
| 条目跨级嵌套需求（章节下再分小节） | 低 | 当前约定一级章节；若出现需求，扫描逻辑扩展一层即可 |
