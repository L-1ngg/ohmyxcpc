# 设计决策记录

## 保留的选型

| 决策 | 选择与原因 |
|---|---|
| 网站 | VitePress，继续使用 Markdown、自动侧边栏和本地搜索 |
| PDF 引擎 | Typst，负责字体、目录、页眉页码及代码跨页 |
| 公式 | Markdown 中写 LaTeX；网页用 mathjax3 v4，PDF 经 mitex 转换 |
| 包管理 | pnpm 与现有 lockfile |
| 发布方式 | 构建时预生成 PDF，再构建纯静态网站；不在浏览器内编译 |

## Issue #1：统一内容源与来源版式

用户选择全量迁入 Templates-XCPC 并独立维护，同时保留完整算法网页。来源采用原生 Typst，如果手工保留其正文章节，再单独维护网页 Markdown，会造成代码和说明漂移。

因此一次性将来源内容转换为 Markdown。独立代码由两端引用同一文件，短示例留在正文，Typst 正文仅为构建产物。来源排版规则单独保留，并适配 OhMyXCPC 项目信息。公式转换可能改变断行与分页，验收采用结构完整性与视觉对照，不要求逐页一致。

网站、整本 PDF 与单章 PDF 共用同一份章节和条目顺序。来源分类和顺序成为新的基线，章内仍拆成独立网页条目。显示代码区域与可独立编译脚手架分别保留，维护时不套用旧模板头改写接口或数值类型。

旧的 `standard` / `double` 以及“整站、章节、页面 × 模板”矩阵已由“整本、章节 × 单一版式”替代。下载中心、章节卡片、CLI 和 PDF 清单一起采用新契约，不提供旧版式与单条 PDF 的兼容层。

## 验证边界

主要通过真实内容输入、公开导出 CLI、静态构建、浏览器与 PDF 文件验证。缺失代码、图片或不支持的结构应显式失败；全量导出失败时保留上一次完整产物，不发布部分清单。

独立代码编译和一次性来源清单核对补充端到端抽样的盲区。浏览器冒烟结果单独报告，因为现有 CI 的冒烟步骤仍允许失败后继续部署。

## 已知限制

- Markdown 到 Typst 转换覆盖本站内容子集，未支持的 token 显式报错。它不是通用 Typst 双向转换器。
- 单章 PDF 对其他章节的引用使用网页链接；本次全书导出中已收录的锚点使用 PDF 内部跳转。
- mitex 0.2.5 在 Typst 0.14.2 下可能输出上游旧符号名称的弃用提示，需要与编译失败、字体缺失区分。
- 含公式的页面沿用 mathjax3 的服务端渲染方式；不能仅凭构建成功推断浏览器没有水合或交互问题。
