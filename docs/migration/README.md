## 转换与核对

一次性转换先由 Typst 编译器求值来源章节，再读取结构化内容树，逐类转换标题、段落、列表、代码、公式、表格、图片和链接。数学字体宏在提取时使用带类型标签的节点保留，公式转换为 LaTeX 后交给现有网页与 PDF 链路。该过程不建立双向编辑或上游自动同步机制。

[content-audit.json](content-audit.json) 保存逐章核对结果：代码块与行内代码按顺序比较内容，图片按顺序比较引用，标题比较数量；说明文本排除公式和代码后，统一空白与引号表现进行比较。19 章均通过该文本核对，独立代码、抽取代码、图片与公共头文件另作字节比较。

这些核对不等于公式等价性证明。公式通过实际编译与代表性视觉对照检查；所有独立 C++ 文件通过 GNU++20 语法检查，但不代表已证明算法正确性。抽取的内联实现仍需要正文说明的模板头、别名或调用上下文。

本次必要的内容规范化只有：

- 将重复来源标签映射为独立网页锚点，内部链接跟随映射。
- 为 4 处粗体边界增加空白，避免 CommonMark 将星号当作正文。
- 将来源中裸写的 `P3209` 链接补成同章已有的 Luogu 完整链接。
- 多行公式转换为 LaTeX `cases`，按位与使用的字面 `&` 转义；全量公式检查覆盖 MathJax 错误节点。

来源的 WIDA、Nemesis、SMU_inch 致谢与作者注释均保留，前言追加直接迁入仓库和提交。来源没有独立许可证声明，迁入不改变原始内容的授权状态。

## 验证入口

- `pnpm typecheck`：Vue 与 TypeScript 类型检查。
- `pnpm test`：公开 CLI 参数、缺失资源、无效代码区域、导出失败保留旧产物、一次编辑同时更新网页和 PDF、有序列表编号等回归。
- `pnpm check:code`：183 个来源独立 C++ 文件的 GNU++20 语法检查。
- `pnpm release`：整本与全部章节 PDF 预生成，然后构建站点。
- `pnpm check:pdf`：实际 PDF 的命名目的地、目录页码、字体、文字越界与出处检查，结果输出到 `pdf/verification/pdf-checks.json`。
- `pnpm smoke`：在构建产物上验证下载、搜索、复制、公式、图片、内部链接和桌面/移动端交互。部署子路径验证时，在构建和冒烟两步使用同一 `VITEPRESS_BASE`。

完整 Chromium 的可见 PDF 阅读器验证可通过 `CHROMIUM_PATH` 选择完整浏览器，配合 `HEADED=1`；无显示器时使用 Xvfb。无头 shell 的空白 PDF 框不能作为 PDF 呈现已通过的证据。截图与 PDF 检查结果放在被忽略的 `pdf/verification/`，不纳入正文或源代码。

CI 沿用原有非阻断浏览器冒烟设置，因此交付时需要单独报告冒烟结果。迁移相关检查在本地执行，远端 CI 与部署仅在后续推送后运行。
