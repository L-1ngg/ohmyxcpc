# OhMyXCPC 当前需求

迁移规格：[GitHub issue #1](https://github.com/L-1ngg/ohmyxcpc/issues/1)。该规格替代旧的多版式、单条 PDF 导出约定。

## 用户与目标

- 模板维护者：维护一份正文与代码，同步生成网站和 PDF。
- 查阅者：通过章节、独立算法页面和全文搜索找到内容，阅读公式、图片和说明并复制代码。
- 参赛队员：预览、下载整本或单章 PDF，按统一版式打印。

## 内容

以 EmptyDust/Templates-XCPC 的固定提交为迁入基线，包含 19 章的算法、说明、公式、表格、图片和出处。迁移后独立维护，具体来源落点见迁移清单。

正文使用 Markdown，数学使用 LaTeX，复用代码使用独立文件。网页和 PDF 展示同一代码区域。章节与条目使用目录及 frontmatter 的 `title` / `order` 定义，扫描结果共同驱动导航、搜索与 PDF 编排。

## 网站

继续使用 VitePress，保留侧边栏、页内大纲、本地搜索、代码复制、深色模式和移动端布局。站点在静态托管子路径下可用。章内算法各有独立页面，算法页提供所属章节 PDF 入口。

## PDF

- 构建时通过 Markdown 到 Typst 转换生成 PDF；正文不手工维护第二份。
- 沿用来源的 A4 单栏正文、双栏目录、章节起页、字体、代码块和页眉页码设计。
- 书名与元数据使用 OhMyXCPC，整本含前言、致谢与来源提交。
- 仅支持整本与章节，每个目标只有一份 PDF。下载中心提供选择、预览和下载，没有版式切换或单条算法 PDF。
- CLI 为 `pnpm export:pdf [章节]`，同时输出首页预览；旧版式和单条参数明确报错。
- 全量预生成只有在所有目标成功后才替换已发布产物及清单；失败返回非零状态。
- 字体由固定来源和 SHA-256 清单准备到项目缓存，本地与 CI 共用。Typst 版本沿用 CI 锁定配置。

## 验收

完整性核对覆盖源码、代码区域和所有正文类别；不能以文件数相同代替内容核对。网页与 PDF 的集成验证通过实际构建产物进行，检查目录、公式、图片、交叉引用和代码展示。来源 PDF 与迁入 PDF 进行代表性页面对照，允许断行、分页与页数变化，不允许内容遗漏、裁切或乱码。

独立 C++ 文件进行 GNU++20 语法检查，依赖上下文的片段另外说明。语法检查不等于算法正确性证明。

## 非目标

自动同步上游、双份正文维护、在线编辑或评测、用户系统、多版式 PDF、单条 PDF、任意算法拼册以及浏览器内编译均不属于当前范围。
